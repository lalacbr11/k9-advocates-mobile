## Completed development

- Booking routes added to the existing profile history in `App.tsx` and
  `src/logic/navigation.ts`. No navigation library was added.
- Dashboard booking cards open Booking Details. For a dog with one booking, the whole
  card is a single tap target. The separate **Profile ›** action still opens the Dog
  Profile, as a sibling control rather than a nested one.
- A dog with several bookings opens a chooser sheet listing each booking's service,
  dates and times, and booking ID.
- `src/screens/BookingDetailsScreen.tsx` follows the Dog Profile layout: 112-point
  photo, name and breed, then owner, service, status, schedule rows, and booking ID.
  Back returns to the previous screen.
- `src/logic/bookingDetails.ts` labels each schedule type: Check-in/Check-out
  (overnight), Drop-off/Pick-up (daycare), Session start/Session end (training).
- The visible New York time-zone explanation was removed from Booking Details and,
  in a later change the same day, from the New Booking form's Schedule section
  (`src/screens/NewBookingScreen.tsx`). Dates and times are still validated and
  interpreted in America/New_York.
- Booking storage remains session-only; bookings added in the app reset on reload.
