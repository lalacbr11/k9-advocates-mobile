# v0.5 Add Booking UI — implementation QA

Date: 2026-10-13. Status: implementation checks passed; visual/product approval pending.

## Scope and data

UI-first, fictional-only, in-memory demo. No SQLite, migrations, backend, navigation
library, Hub access, or architecture-proposal edits. The original nine v0.4 bookings,
client/dog fixtures, approved domain modules, and existing pure schedule selectors
remain unchanged. Generic fictional Training fixtures map to Private Training.

New bookings and notes last only in the current session; reload/restart resets them.
Counter-based session IDs are intentionally temporary. Notes remain outside canonical
booking objects. The presentation adapter retains the existing three Dashboard
filters while the six full service labels appear in the form and booking details.

## Native verification actually performed

Environment: Xcode 16.4, iPhone 16 Pro simulator, iOS 18.6, Expo Go 57.0.9,
SDK 57 and React Native 0.86.3.

A temporary standalone XCTest UI harness in `/tmp/k9-booking-ui-qa` exercised the
running Expo Go app. No test/native project or simulator database was added to this
repository. macOS denied direct Accessibility automation; Xcode's supported UI-test
runner provided the native checks. Temporary captures and result bundles remain
outside Git and contain only fictional data.

Passed scenarios:

- New Booking renders with safe areas, softly colored sections and fixed Save.
- Dog/owner search selects a dog with one tap and closes the sheet.
- Native time wheels preserve 9:17 AM and 4:43 PM exactly, with AM/PM and every minute.
- Notes remain visible above Save while the keyboard is open; full entered text is
  retained, collapse shows Notes added, and reopening restores the text.
- Session saving returns to Dashboard, shows the explicit session-only notice and
  updates the dog/count/movement display.
- Calendar entry preselects October 13, 2026; confirmed session bookings appear in
  its Daily Schedule. An overlapping fictional booking shows expandable read-only
  details. Saving without acknowledgement stays in the form; acknowledging allows
  save and returns to the same Calendar date with the updated booking count.
- Unsaved changes show the discard prompt; Keep editing retains the draft and
  Discard returns to the originating schedule.
- Saving an empty form shows required-field errors. All six service choices expose
  their correct schedule labels. Native date wheels select October 9, 2026 without
  a date shift. The simulator was left on a fresh New Booking screen for review.

Initial exploratory runs exposed accessibility-selector/start-state issues in the
temporary harness. Native inspection also identified wheel-update interruption and
notes scrolling before keyboard resizing; implementation fixes were verified in
subsequent passing scenarios. Final targeted result bundles: 6 (exact minutes/save),
7 (Calendar/conflicts/discard), 9 (notes/keyboard), 10 (six services/date/validation).

## Remaining review and limitations

- Visual approval, physical-device checks, larger Dynamic Type/VoiceOver, landscape,
  and Android behavior have not been completed. This milestone targets iPhone.
- Multiple conflicts and incomplete checking are regression-tested in pure logic;
  the native warning scenario used one verified fictional overlap. No simulated
  conflict result or malformed database example is injected into the UI.
- DST gap/fold rejection and device-independent date helpers are automated tests.
  The full multi-device-zone Expo Go timezone gate for future SQLite implementation
  remains outstanding; this task does not claim it passed.
- The Calendar retains its v0.4 October 2026 starting month and next-six-month loading.
  Dates before that starting month are not browsable in the existing Calendar UI.
  Tracked as EOD-03 in the end-of-day update.
- Later on 13 October, Dashboard → Dog Profile navigation was added after this record.
  Its verification and the current open-issue list are in the end-of-day update in
  `docs/qa/v0.5-ui-revision-1-qa.md`.
- No booking edit/cancel/restore UI or durable notes/history is included.
- npm reported 23 dependency vulnerabilities (7 moderate, 16 high) during picker
  installation. No automatic or breaking dependency upgrades were applied.

tap a Calendar day and use Add Booking on Daily Schedule. Try Willow / Dog Daycare /
October 9, 2026 / 9:17 AM–4:43 PM to review an actual overlap within the fictional
session fixtures. Test notes collapse, required fields and Back/discard. Reload to
reset all in-memory additions. Use fictional text only.
